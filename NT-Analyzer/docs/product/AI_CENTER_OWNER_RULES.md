# AI Центр — правила владельца

Правила продиктованы владельцем 18.09.2026 и описывают, каким должен быть
AI Центр (мир агентов). Это продуктовые требования, а не описание текущего
кода: статус каждого правила указан по таксономии
[DOCUMENTATION_GOVERNANCE.md](../DOCUMENTATION_GOVERNANCE.md).

**Порядок изменения.** Любое правило из этого документа меняется только после
явного подтверждения владельца. Если реализация требует отступить от правила,
исполнитель сначала спрашивает владельца, а не меняет поведение сам.

## 1. Первый вход и подключение модели

| # | Правило | Статус |
|---|---|---|
| 1.1 | У нового пользователя нет своих моделей. Первый экран предлагает одно действие — «Подключить модель». | `PLANNED` |
| 1.2 | При подключении выбирается тип: **по API** или **локально**. Локальные модели показаны, но помечены «в разработке», пока подключение не доведено. | `IN DEVELOPMENT` |
| 1.3 | Подключение по API: выбор провайдера из списка (OpenAI, Anthropic, Google, DeepSeek, xAI, Mistral, OpenRouter) или «другой совместимый сервис» с адресом; вставка ключа; ключ проверяется сразу, список моделей подтягивается автоматически; пользователь выбирает модель и может дать ей имя. | `IN DEVELOPMENT` — в коде есть подключение текстовых моделей по совместимому HTTPS API; автоподтягивание списка моделей и мастер ещё не сделаны |
| 1.4 | После ввода ключа модель тестирует себя сама одним коротким запросом: связь, ответ, стоимость запроса. Данные стратегий в тесте не используются. | `PLANNED` |
| 1.5 | При подключении указывается, как оплачивается доступ: оплата по токенам с потолком расходов за день/неделю/месяц; фиксированный лимит на неделю или месяц; бесплатно с дневным лимитом (запросы или токены); грант или кредит (сумма и срок действия, например для студентов). По умолчанию предупреждение при расходе 80% лимита. | `PLANNED` |
| 1.6 | Новая модель помечена «новая, рейтинга нет», пока нет проверенных задач. | `PLANNED` |

## 2. Общая модель владельца

| # | Правило | Статус |
|---|---|---|
| 2.1 | Владелец может поделиться своей моделью со всеми пользователями. | `PLANNED` |
| 2.2 | У пользователя без своих моделей общая модель владельца работает как его Управляющий и ведёт с ним личный чат. Рядом всегда видно приглашение подключить свою модель. | `PLANNED` |
| 2.3 | Ограничения на общую модель (лимиты, кто может пользоваться) — отдельное решение владельца, до него не вводятся. | `PLANNED` |

## 3. Статистика модели

| # | Правило | Статус |
|---|---|---|
| 3.1 | По каждой модели видно: расход токенов и денег, число задач, рейтинг, где чаще всего работала (под каким агентом: Управляющий, Заместитель, специалисты), под каким агентом у неё лучший и худший результат. | `IN DEVELOPMENT` — в UX-сборке вкладка «Модели» — таблица всех моделей из реестра «AI агенты» (у владельца их 20): где работает, запросы за месяц, успешность, расход, остаток квоты или гранта, последний раз; карточка модели — тариф, под какими агентами работала, последние вызовы. Меньше трёх вызовов — NEW |
| 3.2 | Плохо работающую модель можно выключить; история её задач сохраняется. | `PLANNED` |
| 3.3 | Модель не закреплена за должностью, пока владелец или пользователь сам её не закрепил. Показывается, где модель работала и насколько успешно под каждой должностью. Предложение исполнителя по циклу (ждёт подтверждения владельца): закрепление важнее всего; новая модель проходит пробный круг — по 3 задачи в каждой открытой должности (Исследователь, Кодер, Бэктестер, Оптимизатор, Новости); дальше в должность идёт модель с лучшим успехом именно там, 10% задач — на пробу других; ответственные должности (Управляющий, Бухгалтер, Судьи) — только модели от 20 вызовов с успехом от 90%; специальные модели (поиск по памяти, озвучка) в текстовые должности не попадают. Роли из старого реестра «AI агенты» закреплением не считаются: решением владельца от 20.09.2026 они переведены в архив (правило 3.4). | `PLANNED` — правила цикла требуют подтверждения владельца; в UX-сборке таблица показывает, как они ложатся на текущие модели |
| 3.4 | Указание владельца 20.09.2026: старый реестр «AI агенты» переведён в отдельный архив только для чтения. Ничего из старых данных не удаляется и не переписывается. Архив нужен, чтобы видеть прежнее устройство, проверять старые назначения моделей и ролей, смотреть историческую статистику, расследовать расхождения после миграции и сверять новую систему со старой. | `IN DEVELOPMENT` — `app/ai_lab/legacy_archive.py`: копия с SHA-256 по каждому файлу, источник не трогается; `tools/legacy_registry_migrate.py` |
| 3.5 | Миграция переносит только исторические факты: модели, провайдеры и подключения там, где это безопасно, история выполненных задач, результаты, расходы и usage, оценки с подтверждаемым происхождением, связи «какая модель фактически работала под какой старой ролью» — исключительно как historical provenance. | `IN DEVELOPMENT` — `app/ai_control_center/legacy_migration.py`; оценки без подтверждаемого происхождения остаются в архиве с указанием причины |
| 3.6 | Как действующая конфигурация не переносится ничего: старые должности, старые автоматические назначения, старые правила маршрутизации, старые связи Model ↔ Role. Новые Agent Roles создаются по действующим правилам владельца, а не миграцией. Секреты остаются в защищённом хранилище. | `IN DEVELOPMENT` — отказы перечислены в отчёте сверки поимённо |
| 3.7 | После миграции выполняется сверка «архив → отчёт миграции → новый реестр»: сколько записей было, сколько перенесено как история, сколько сознательно не перенесено, какие новые сущности созданы, нет ли потерянных задач, результатов и статистики, нет ли модели, ошибочно закреплённой за новой должностью. Новый реестр становится единственным рабочим только после того, как сверка сошлась. | `IN DEVELOPMENT` — отчёт `migration-report.json`, признак включения — файл `legacy-migration.ok.json`; на данных владельца 20.09.2026: 20 моделей, 234 вызова, 9 связей-provenance, потерь нет |
| 3.8 | Архив остаётся доступен через отдельный просмотр `Legacy / Архив` и никогда больше не участвует в Router, Coordinator, рейтингах текущих назначений и исполнении задач. | `IN DEVELOPMENT` — просмотр в отдельной вкладке «Задачи», только чтение; тест удерживает, что архив не читается кодом работающей системы |

## 4. Команда и иерархия

| # | Правило | Статус |
|---|---|---|
| 4.1 | После подключения первой модели сразу появляется иерархия агентов с лицами. Лица и имена генерируются автоматически; пользователь может изменить имя и фото любого агента. | `IN DEVELOPMENT` — в UX-сборке иерархия во вкладке «Команда», у «Вы» — фото владельца; пустое место нанимается в два шага: лицо и имя (имя предложено), обязанности заложены в должность на сервере; автоматическое создание новых лиц не сделано — выбор из готовых |
| 4.6 | Указание владельца 19.09.2026: добавляя агента, владелец выбирает только должность, лицо и имя (или берёт предложенное). Всё остальное — обязанности, критерии судей, порядок работы разработчика стратегий — заложено в должность и не заполняется вручную. | `IN DEVELOPMENT` — UX-сборка: `team_roles.py` |
| 4.7 | Кнопка «Сформировать команду автоматически»: всем свободным местам — случайное имя и стандартное фото (своё фото можно выбрать потом). Ниже иерархии — таблица персонала: задачи, рейтинг, одобрено/отклонено, модели под агентом, последняя работа. | `IN DEVELOPMENT` — UX-сборка |
| 4.2 | Иерархия: Пользователь ↔ Управляющий (правая рука, имя задаёт пользователь, по умолчанию Витёк) → Заместитель (курирует всех) и Секретарь (протокол, журнал) → три отдела. **Разработка стратегий:** Исследователь, Квант-аналитик, Кодер NinjaScript, Ревьюер кода, Бэктестер, Оптимизатор. **Операции:** Бухгалтер, Новостной аналитик, Оператор графиков. **Судьи:** Судья статистики, Судья риска, Главный арбитр. | `PLANNED` — в коде уже есть Управляющий, Заместитель, Секретарь и персоны Марина, Толик, Никита, Иван ([AGENT_PERSONAS.md](../AGENT_PERSONAS.md)) |
| 4.3 | Пользователь общается только с Управляющим. Управляющий передаёт задачу Заместителю; Заместитель распределяет её по отделам; исполнители отчитываются Заместителю; Заместитель проверяет, сжимает итог и передаёт Управляющему; Управляющий отвечает пользователю. Прямые ответы других агентов пользователю по умолчанию не используются. | `PLANNED` |
| 4.4 | Если внутри любого процесса возникает проблема или спор, вопрос уходит судьям; их решение возвращается Заместителю. | `PLANNED` |
| 4.5 | Занятые агенты подсвечиваются. Клик по агенту открывает короткую карточку: какие модели под ним работали, насколько успешно, какие были ошибки. | `IN DEVELOPMENT` — в UX-сборке занятые и ожидающие проверки агенты подсвечены в иерархии и в нижней полосе; клик открывает карточку агента: состояние (включён, свободен или работает, что ждёт владельца), модели под агентом с успешностью и ошибками, проверки с классом задач и размером выборки |

## 5. Цели и задачи

| # | Правило | Статус |
|---|---|---|
| 5.1 | Работа начинается с цели: «Добавить цель», свой текст, срок (месяц, квартал, год). | `IN DEVELOPMENT` — в UX-сборке «Добавить цель» открывает панель: цель своими словами, срок (месяц, квартал, год), сумма и задача на неделю; цель хранится в данных рабочего пространства и меняется там же |
| 5.2 | Прогресс цели по прибыли считается **только по стратегиям, которые торгуют на демо-счёте**; бэктесты в прогресс не входят. Прогресс показан шкалой. | `PLANNED` — шкала и сумма показаны, но прибыль демо-счёта в прогресс ещё не заведена: прогресс остаётся нулевым, и это подписано в углу |
| 5.3 | После добавления цели главный агент автоматически формирует одну задачу на неделю — одним предложением (например, уточнить у владельца, какие стратегии разрабатывать). | `PLANNED` — задачу на неделю пока записывает владелец в той же панели; автоматически её формирует Управляющий на следующем этапе |
| 5.4 | Задачи на сегодня формируются в диалоге с владельцем. Цель, задача недели и задачи на сегодня видны компактно в углу экрана. | `IN DEVELOPMENT` — в UX-сборке правый столбец повторяет прототип: цель, задача недели, задачи сегодняшнего дня; пока цели нет, ячейки подписаны «Цель ещё не задана», а «Добавить цель» сообщает, что цели появятся на следующем этапе |
| 5.5 | Первый старт: после первой цели все агенты фиксируют исходное состояние (Бухгалтер сверяет все базы, включая нулевые значения; Новостной аналитик загружает календарь; остальные — свои стартовые записи). | `PLANNED` |
| 5.6 | Указание владельца 19.09.2026: в «Ошибках и предупреждениях» и в очереди «Задач» — только вопросы Управляющего к владельцу: уточнение поручения, срок под угрозой, возникшая проблема, нужное решение. Тестовые проверки системы решаются сами и владельцу не показываются (их можно раскрыть отдельной ссылкой в «Задачах»). Нажатие на вопрос открывает чат с Управляющим по этой задаче. | `IN DEVELOPMENT` — UX-сборка: чат по задаче, если сервер может его открыть, иначе чат Управляющего с подставленной сводкой вопроса |

## 6. Главный экран мира агентов

| # | Правило | Статус |
|---|---|---|
| 6.1 | Одностраничный экран мира агентов: живая иерархия, где видно, кто сейчас работает и как агенты взаимодействуют. | `IN DEVELOPMENT` — вариант B во вкладках, UX-сборка |
| 6.2 | Терминал «хода работы»: журнал действий нейросетей (кто, кому, через какую модель, сколько токенов, что сделал). Скрытая цепочка рассуждений моделей не публикуется — показываются наблюдаемые шаги. | `IN DEVELOPMENT` — в UX-сборке «Ход работы» внизу строится из реальной ленты действий рабочего пространства; поток событий оркестратора в реальном времени ещё не подключён |

| 6.4 | На экране компактно: память и уроки (с графом знаний), недавняя активность, ошибки и предупреждения, исследования (семейство → гипотеза и цели исследования → оценённые стратегии → чемпион с параметрами). | `IN DEVELOPMENT` — в UX-сборке «Исследования» читают каталог Лаборатории AI (только владельцу; у владельца 11 семейств и 22 стратегии); «Память» — записи команды и база знаний Лаборатории: общие правила разработки стратегий, уроки, эталонные стратегии, материалы исследований (граф и список) |
| 6.5 | Терминал и подсветка занятых агентов строятся из реальной шины событий оркестратора (запрос, старт модели, ответ, таймаут, эскалация), а не имитируют работу. | `PLANNED` |
| 6.6 | Вкладка «Исследования» — это и есть лаборатория создания стратегий: этапы (гипотезы → в разработке → прошли пороги → одобрены для демо → архив), стратегии каждого семейства с результатами, создание нового исследования на месте. Ссылки на отдельную страницу Лаборатории нет. | `IN DEVELOPMENT` — UX-сборка |
| 6.7 | В памяти эталонная библиотека (образцы стратегий из открытых источников, которые только компилируются и проходят проверки) отделена от реестра наших стратегий; «Стратегий в памяти» считает только наши. Граф знаний объёмный, его можно вращать; новые документы появляются новыми ветвями. | `IN DEVELOPMENT` — UX-сборка |
