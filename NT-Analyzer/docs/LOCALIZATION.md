# Документация: язык и локализация


## Canonical language

**Русский — канонический язык** пользовательской, product- и
governance-документации StratForge. Новые user/product/governance документы
пишутся по-русски. Технические архитектурные документы могут содержать
англоязычные термины, но пользовательские формулировки, законы и governance —
на русском.

## Что НЕ переводится (остаётся как есть)

- имена API и endpoints (`/api/admin/releases`, `POST .../rehearse-bluegreen`);
- названия классов, функций, модулей (`release_center`, `_require_governance_manage`);
- поля БД и таблицы (`sf_release_artifacts`, `scope_type`, `docs.manage_global`);
- команды, флаги и переменные окружения (`DEPLOYMENT_ENV`, `git mv`);
- пути файлов и идентификаторы (`docs/operations/…`, `GOV-RISK-001`);
- код, конфигурация, машинные значения.

## Что нельзя менять ради перевода

Смысл законов, safety limits и утверждённых governance-правил **не меняется** при
любой языковой нормализации. Governance-законы имеют машинный источник истины
`data/governance/laws.json`; перевод/переформулировка не должны затрагивать
числовые значения, аудиторию (`audience`) или семантику правила. Изменение
governance-документов проходит owner / `docs.manage_global` gate и пишет запись
в `data/governance/change_log.jsonl` (см. `docs/DOCS_STRUCTURE.md`).

## Структура локализации (без расходящейся копии)

- **Единый canonical source на русском.** Не создаётся вручную вторая
  англоязычная копия документа, которая начнёт расходиться. Один файл — один
  источник истины.
- Если в будущем понадобится английская версия для внешней аудитории, она
  генерируется/поддерживается как **производная** от русского canonical source
  (например, отдельный `l10n/en/`-слой поверх canonical), а не как параллельно
  редактируемый дубль. До появления такого процесса английские версии не
  заводятся.
- Governance rendered-файлы (`docs/governance/*`) остаются генерируемыми из
  `data/governance/*`; их нельзя редактировать вручную.

## Текущий статус нормализации (честно)

- Governance-документы (`docs/governance/*`) и документы агентов (`docs/agents/*`)
  уже на русском.
- Часть architecture/operations/product документов — смешанные RU/EN или
  английские. Полный проход нормализации по каждому техническому документу — это
  follow-up (см. `docs/current/NEXT_ARCHITECTURE_FINAL_REQUIREMENTS_MATRIX.md`
  §D, «Russian normalization … PARTIALLY IMPLEMENTED»). Эта фаза устанавливает
  политику и структуру; массовый рерайт технических документов не выполнялся,
  чтобы не исказить смысл контрактов.
