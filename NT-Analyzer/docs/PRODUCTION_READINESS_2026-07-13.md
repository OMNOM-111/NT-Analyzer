# Production readiness — 2026-07-13

## Итог

Локальный owner-контур готов к финальной ручной приёмке и повседневной работе.
Витёк, StratForge Orchestrator, Telegram, Aurora, workspace isolation,
NinjaTrader bridge и фоновый watchdog проверяются одним release-набором.
Открытых GitHub issues, review comments и review threads на момент аудита нет.

## Фактическая архитектура

1. Владелец или пользователь пишет в Aurora либо Telegram.
2. Единый StratForge Orchestrator gateway определяет identity, workspace,
   capability и адресата.
3. Витёк является единственным owner-facing управленческим собеседником.
4. Управляющий распределяет независимые задания между профильными агентами;
   до шести дорожек могут работать одновременно.
5. Результат возвращается один раз, человеческим языком. Внутренние ID, модели,
   severity и служебный маршрут остаются в аудите.

Витёк не выполняет полный опрос каждые пять минут. Bridge, job queue, Telegram
и приложение записывают сигналы в долговечную событийную очередь. Полный scan
выполняется при запуске или по явной команде. Временные окна показывают, когда
каждая готовая стратегия может работать и где остаются пустые промежутки.

## Сохранность и изоляция

- Диалоги адресуются по `user_id + workspace_id + conversation_id`.
- Старые owner-диалоги мигрируются в scoped storage один раз и без дубликатов.
- Non-owner не получает owner history, задачи, планы или runtime.
- Истёкшая браузерная сессия показывает Telegram login и не очищает чат.
- `accounts.dpapi` привязан к Windows CurrentUser; на другом ПК нужен новый
  вход, а не копирование сессии.
- Runtime, секреты, Telegram offsets, события и рабочие данные не коммитятся.

  ForEach-Object { node --check $_.FullName }

Дополнительно проверяются локальные Markdown-ссылки, единая cache-version
`api.js`, отсутствие inline scripts/handlers, auth/CSRF/workspace contracts и
реальные ветки решения Витька `да/нет`.

## Безопасная ручная приёмка

Встроенный браузер Codex для этого workspace не используется: 13 июля 2026 года
он несколько раз приводил к зависанию/закрытию Codex. Пользователь открывает
`http://127.0.0.1:8765/ui/` в обычном браузере и проверяет:

1. При необходимости проходит отдельный Telegram-вход командой `/login КОД`.
2. Видит прежнее имя `StratForge Orchestrator`, список чатов и историю.
3. Пишет: «Витёк, перечисли нерешённые задачи».
4. На один вопрос отвечает `да`, на другой `нет` и видит ровно одно
   соответствующее действие/подтверждение.
5. Открывает стратегии и проверяет статус Витька, активных агентов и временные
   окна.
6. Повторяет сообщение в Telegram и убеждается, что ответ и история совпадают.

Этот smoke не запускает live trade, не удаляет профили и не классифицирует
финансовые записи.

## Осознанные неблокирующие ограничения

- `stress_pass_flag` остаётся `null`, пока отдельный stress-run не приложил
  проверяемый результат. Это fail-closed поведение: отсутствие evidence не
  считается успехом и не разрешает продвижение стратегии.
- Автоматическая разработка стратегии для пустого временного окна намеренно не
  запускается; владелец ставит такую исследовательскую задачу отдельно.
- Hosted control plane, внешний payment checkout, перенос всех тяжёлых LLM/
  backtest задач в worker, adaptive polling/SSE и полный security threat matrix
  остаются дальнейшими фазами. Они не нужны для текущего local-first owner
  запуска, но перечислены в
  [resilience backlog](RESILIENCE_SECURITY_BACKLOG_2026-07-10.md).
- Визуальная ручная приёмка остаётся действием пользователя в обычном браузере;
  автоматизированные HTTP/DOM/API проверки не заменяют субъективную проверку
  внешнего вида.
- Глобальный пользовательский Python содержит посторонний `pandas-ta 0.4.71b0`
  с несовместимыми для него версиями `numba/numpy`. NT-Analyzer не импортирует
  эти пакеты и не перечисляет их в `requirements.txt`; чистый CI устанавливает
  только проектные зависимости. Этот внешний конфликт не исправляется из
  репозитория, чтобы не повредить другие пользовательские проекты.

## Операционный запуск

Один раз выполните `00_INSTALL_VITEK_BACKGROUND.cmd`. Windows task
`StratForge Vitek` поддерживает backend и событийный worker после входа в
систему, не открывая браузер. Состояние доступно через `GET /api/health`, лог —
`logs/vitek-background.log`. Основные инструкции:
[Витёк](VITEK.md), [операции Aurora](UI_OPERATIONS.md),
[Telegram Mini App](TELEGRAM_MINI_APP.md).
