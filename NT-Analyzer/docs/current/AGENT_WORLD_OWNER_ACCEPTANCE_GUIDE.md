Канонический объём и ограничения: [AGENT_WORLD_IMPLEMENTATION_STATUS.md](AGENT_WORLD_IMPLEMENTATION_STATUS.md).
Визуальное соответствие макетам пока не принято; этот маршрут не изменяет исходный план.

## 4. SF Chat → задача → результат → проверка

Статус браузерного прохода: **NOT YET OBSERVED**. Использовать только уже разрешённое подключение; режим записать до запуска.

1. [ ] «Модели» → выбрать подключение → «Первое задание». Указать «Независимая проверка» и вход; разрешить отправку только выбранному подключению в существующем бюджете.
2. [ ] «Работа» → карточка задачи → «Открыть в SF Chat»: записать один Task ID. Пока идёт исполнение, сверить «Обзор», «Работа», профиль и сообщение чата: один и тот же запрос, состояние и счётчик выполняемых задач.
3. [ ] После ответа открыть «Артефакты» и «Оценка». Проверить источник, фактическую модель/исполнитель, класс задания и стоимость. `Неизвестно` не заменять нулём.
4. [ ] До ручной проверки увидеть «Ожидает вашей проверки» / «Ожидает проверки», а не приёмку всей работы; сверить ожидающие проверки во всех четырёх представлениях.
5. [ ] «Проверить полученный результат» → «Ваше решение по этому результату» → принять либо отклонить с комментарием. Проверить отражение того же решения и истории в карточке и SF Chat.
6. [ ] У завершённой проверки не должно оставаться фиктивного ожидания, но это решение не выдаёт новых прав и не принимает другие результаты.
7. [ ] Отдельный согласованный ошибочный запрос: открыть «Ошибки», проверить сообщение и счётчики. Если сервер разрешил «Новая безопасная попытка», создать её; старый Task ID и исходная ошибка остаются в истории.
8. [ ] При неизвестном исходе внешнего действия безопасный повтор не должен становиться доступным автоматически. Повтор отправки того же подтверждённого действия не создаёт лишний вызов.

### Источник оценки и реальные работы

- [ ] «Агенты» → «Проверочный рейтинг»: проверить класс задач, размер выборки, происхождение проверки и окно наблюдения. Три успешных «Арифметика · JSON» — только диагностика, не 100% профессионального качества.
- [ ] `agent-world-local-test-executor-v1`, `SYNTHETIC`, `external_call=false` — локальный тестовый исполнитель, не ответ внешней модели. Не объединять такую выборку с реальными вызовами.
- [ ] Для реального модельного задания проверить фактический receipt/ответ разрешённого провайдера, автоматическую проверку и отдельное решение человека; появление одной записи или HTTP 200 недостаточно.
- [ ] Реальный бэктест через назначенную Persona в SF Chat: дождаться завершения существующего бэктестирования, открыть исходный отчёт, проверить инструмент, период, источник данных и итоговый статус.
- [ ] Реальный снимок графика: убедиться, что в сообщении SF Chat есть настоящий PNG из разрешённого сценария графика, он открывается и относится к нужному графику/задаче. PNG не заменять SVG-заготовкой или нарисованной статистикой.
- [ ] Бэктест и PNG подтверждают результат соответствующего приложения; сами по себе они не доказывают качество модели. При отсутствии разрешённого Connector/данных записать конкретный blocker без synthetic замены.

## 5. Persona, речь, подключение своей модели

Статус браузерного прохода: **NOT YET OBSERVED**.

- [ ] «Агенты» → «Создать / изменить Persona»: создать своё имя, назначение, стиль, «Лицо персоны» и при необходимости «Роль в приложении». Сохранить, закрыть, снова открыть.
- [ ] Persona, Agent Role, Provider Account, Model и «Внешний агент» отображаются отдельно. Смена модели/Router не меняет лицо и речь исходной Persona; вклады специалистов сохраняют назначенные им роли.
- [ ] Проверить прежние аватары и настройки Persona без сброса. В «Лицо и голос Persona» нажать «Прочитать описание», затем «Остановить звук»; записать фактически услышанный режим, ошибку или fallback.
- [ ] Локальный голос устройства не является копией серверного голоса; сохранённая настройка не доказывает звук. Готовый разговорный клип не означает настоящий lip-sync; он обозначен как недоступный без таймингов.
- [ ] Под обычным тестовым пользователем открыть «Модели» → «Подключить модель»: «Название подключения», «Тип подключения» («Своя модель» / «Внешний агент»), «Провайдер», «Идентификатор модели», «Endpoint», «Ключ подключения», «Persona».
- [ ] Мастер содержит подсказку OpenRouter и ссылку на страницу отдельного ключа. Ключ владелец вводит **сам в password-поле «Ключ подключения»**, не в SF Chat; для стандартного провайдера Endpoint оставить пустым.
- [ ] Пока отдельный ключ не введён: проверить поля, валидацию и отсутствие owner-ключей; реальное подключение и ответ отметить `NOT TESTED — ожидается отдельный пользовательский ключ`.
- [ ] После ввода владельцем: «Проверить соединение» → «Первое задание» → ответ и review. Отдельно проверить поддержанный тип «Внешний агент»; выбор типа сам по себе не доказывает произвольный удалённый протокол или автономность.

## 6. Coordinator, Router, Execution и Court

Статус браузерного прохода: **NOT YET OBSERVED**. Только доступные серверные действия; не включать флаги ради карточки PASS.

- [ ] «Автоматизация» → «Новое поручение Координатору»: новая цель, JSON-массив чисел, подключение Координатора, отдельные проверяющие, параллельные связи или цепочка. Этот сценарий — числовая сводка и проверка передачи фактов, не универсальное планирование.
- [ ] После исходного ответа открыть «Проверить план делегирования»: увидеть роли, операции и источник. До «Разрешить этот план» дочерние задания не запускаются; согласие не поднимает бюджет или права.
- [ ] После явного разрешения открыть «Общий результат и вклады»: отдельные Contributions/источники и обязательные проверки. Принять исходные результаты отдельно, затем общий снимок; агрегат не принимается автоматически.
- [ ] Отзыв, истечение разрешения, изменение источника, глубина/цикл или лимит дают понятную остановку с историей, не новое неявное разрешение. Повтор чтения не создаёт граф заново.
- [ ] Карточка исходной модельной задачи → «Выбор подключения · Router» → «Предпросмотр выбора»: запусков ещё нет. Проверить выбранное подключение и происхождение через детали.
- [ ] «Разрешить новый запуск» создаёт новую задачу по **этому** показанному выбору; старый результат сохраняется. При изменении источника/Persona/разрешений требуется новый предпросмотр. Повтор подтверждения не дублирует вызов.
- [ ] «Система»: для Router, Execution V2, делегирования и расписаний сверить отдельно «Реализовано», «Включено», «Доступно сейчас», «Рабочий режим». Legacy worker не равен активному Execution V2.
- [ ] Для разрешённого Execution V2 открыть evidence: план/claim, фактический исполнитель, обнаруженное отклонение или результат, разрешённые действия. Нельзя засчитать V2 только по наличию очереди.
- [ ] «Решения / Court» → «Новое решение» с доказательствами → «Проверить через Court» с тремя независимыми проверяющими, если это разрешено. Проверить реальные отдельные ответы/источники и вердикт; он не исполняет сделку и не заменяет полномочия владельца.

## 7. Память двух пользователей, проекты, расписание и SF Social

Статус браузерного прохода: **NOT YET OBSERVED**.

- [ ] В «Память» пользователь A создаёт личную запись с целью и сроком хранения. Пользователь B в отдельной сессии не видит её текст или артефакт; проверять один и тот же workspace, а не только разные workspace.
- [ ] После явного «Опубликовать в workspace» B видит отдельную общую запись и происхождение. Отозвать её или источник: доступ прекращается, личный источник и история сохраняются. Preview SQLite не является доказательством PG/RLS.
- [ ] «Strategy Projects» → «Создать проект» → «Новая версия»: сверить параметры и старую версию после повторного открытия; создание проекта не запускает торговое исполнение.
- [ ] «Рутины» → «Предложить рутину» и «Календарь» → «Добавить событие»: предложение и событие не означают работающий планировщик.
- [ ] «Автоматизация» → «Проверить расписание»: исходная задача SF Chat, модель, конечное число запусков, срок разрешения, стоимость. Только затем явное «Включить по расписанию» при уже выданном разрешении.
- [ ] Наблюдать фактический due-запуск, новую задачу и историю; проверить отмену/отзыв и конечность. Перезапуск/lease/recovery отметить отдельно по серверному evidence, не по одной карточке расписания.
- [ ] «В SF Social» → «Подготовить публикацию»: выбрать только проверенный источник и открыть неизменяемый снимок. До отдельного подтверждения пост не создан.
- [ ] Проверить комментарий и «Кто увидит публикацию». Конкретную постоянную публикацию подтверждает владелец кнопкой «Опубликовать в SF Social»; личная память, ключи и сырой payload не публикуются.
