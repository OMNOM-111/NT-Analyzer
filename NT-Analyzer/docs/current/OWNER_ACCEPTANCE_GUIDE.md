# Agent World — маршрут проверки владельцем

Статус: **IN DEVELOPMENT**. Это маршрут финальной проверки, а не подтверждение
приёмки. Единственный оперативный статус и результаты проверок находятся в
[AGENT_WORLD_MASTER_STATUS.md](AGENT_WORLD_MASTER_STATUS.md).

## Изоляция и достоверность

Финальный адрес и SHA будут указаны после общих проверок. Local `8765` не
переключается. Приёмочная база, пользователи и результаты отдельные; owner-ключи
не копируются. Development-ответы отмечены `SYNTHETIC`: это доказательство
работы механизма, не профессионального качества модели и не разнообразия
провайдеров. Отсутствие достаточной выборки должно показываться как отсутствие
данных, а не как 100% качества.

## Последовательность

| Шаг | Куда нажать | Ожидаемый результат и evidence |
| --- | --- | --- |
| 1. Обзор | AI Center → Обзор | Счётчики соответствуют текущим задачам; ожидающие проверки не скрываются. Детали сохраняют ID и ошибки. |
| 2. Persona и чат | Агенты → Persona → создать/открыть → SF Chat | Имя, псевдоним, роль, аватар и голос отдельны от модели и подключения. История остаётся при переключении модели. Голос проверяется прослушиванием, не только HTTP. |
| 3. Intent | SF Chat → «Координатор: Проверь мои числа» → «Уточнить данные и ожидаемый результат» | Цель загружается из исходного сообщения. Введите числа через запятую, выберите подключения и смысловой вариант. Без подтверждения задача не запускается; технические ID и JSON вводить не нужно. |
| 4. Координатор | Подтвердить поручение → проверить план → разрешить план | Дочерние задачи связаны с исходным Intent. До отдельного разрешения плана дочерних запусков нет. В деталях — связи родитель/ребёнок и хеш плана. |
| 5. Результат | Карточка задачи → результат → SF Chat | Сообщение и карточка ссылаются на одни Task, Contribution, Outcome; повтор доставки использует сохранённый результат. |
| 6. Проверка | Проверить полученный результат | Получение результата не равно принятию. До действия владельца статус проверки ожидающий; после — история сохраняет оценку и основания. |
| 7. Репутация | Агенты/Модели → статистика | Отдельные субъекты оценки, класс задач, размер выборки, период, происхождение. Diagnostic не превращается в field performance. |
| 8. Court | Решения → проверить через Court | Неизменяемый пакет, три изолированные сессии, голоса, уверенность и dissent доступны в деталях. Court не запускает исполнение. Synthetic не подтверждает три реальных провайдера. |
| 9. Память | Память → открыть/продвинуть/отозвать | Область, источник, TTL, верификация и supersedes видимы. Повторить под вторым обычным пользователем: чужое workspace не раскрывается. |
| 10. Автоматизация | Предложение процесса → принять → в принятой Рутине/Календаре «Проверить расписание» → «Включить по расписанию» | План привязан к принятой записи и её ревизии. Принятие предложения не включает расписание. Нужны отдельные согласие и полномочия. После выполнения остаются результат и история; отзыв запрещает следующий запуск. |
| 11. Внешний агент | Внешние агенты → добавить → заполнить Development-агентом → проверить | ACTIVE → первое задание → Contribution/Outcome/Evaluation → статистика → отзыв → следующий запуск запрещён. Подключение не является Model; неизвестная внутренняя модель — externally managed. |
| 12. Собственная модель | Модели → подключить | Отдельный обычный пользователь и пустое поле секрета. Владелец вводит тестовый ключ самостоятельно. Затем проверка соединения, задание, история и отзыв. Без ключа только этот реальный сценарий ожидает проверки. |
| 13. SF Social | Проверенный результат → подготовить снимок | До явного подтверждения только предпросмотр. Проверяются disclosure, provenance, хеши и отсутствие личной памяти. Настоящая постоянная публикация остаётся действием владельца. |
| 14. Owner Preview | Preview → New User → каждый способ регистрации | Telegram, Google, e-mail/OTP, QR; согласие вручную, Device Confirmation, permanent/session. Reset разделяет сценарии; Exit возвращает исходную identity и данные приёмочного owner. |
| 15. System | System → механизмы, ошибки и ограничения | Фактические режимы Router/Execution/Delegation/Scheduler и workspace-флаги. Legacy worker не означает Execution V2; выключенные защитные механизмы не получают зелёный статус. |

## Отдельные ожидающие действия

Для собственного тестового подключения можно выбрать поддерживаемый DeepSeek.
Официальная [API-платформа DeepSeek](https://www.deepseek.com/platform/) ведёт к
созданию ключа; [документация API](https://api-docs.deepseek.com/api/deepseek-api/)
описывает его применение. Это не обещание бесплатного тарифа. В мастере
«Модели → Подключить» ключ вводится только в поле **«Ключ подключения»**;
актуальное имя модели берётся из каталога сервиса. В чат секрет не отправляется.
Приёмочная диагностическая сборка блокирует внешнюю сеть: реальная проверка
нового ключа проводится отдельным разрешённым тестом после его ввода, не
подменяется ответом локального test executor.

- Настоящее завершение регистрации и ввод отдельного тестового ключа владельцем.
- Прослушивание голоса, если автоматическая среда не может подтвердить звук.
- Реальная межпровайдерная проверка Court/Router при наличии отдельных подключений.
- Решение владельца о бюджете remote external-agent; текущий запрет не обходится.
- Подтверждение конкретной постоянной публикации настоящего результата.
- Visual P3: полное соответствие макету пока не принято; этот маршрут не меняет
  исходный дизайн-план и не является его формальной приёмкой.
