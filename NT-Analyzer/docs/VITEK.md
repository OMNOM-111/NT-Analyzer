# Витёк — правая рука руководителя

Витёк — единственный собеседник владельца и верхний управленческий слой системы.
Иерархия: **владелец → Витёк → Управляющий → профильные агенты и инструменты**.
`StratForge Orchestrator` остаётся названием общего интерфейса и единого шлюза,
как и в прежней версии приложения. Внутри него с владельцем разговаривает Витёк;
Orchestrator не является отдельным начальником или вторым собеседником. Витёк принимает все результаты, отвечает за итог,
выбирает, что действительно нужно донести владельцу, и поручает Управляющему
организовать исполнение.

Любая фраза из приложения или Telegram технически проходит через единый шлюз,
но пользователь всегда разговаривает с Витьком. Поддерживаются обращения `Витёк`, `Витек`, `Витя`,
`Витька`, `Витенька`, `Vitek`, `/vitek` и `дежурный контролёр`. Ответ в общей
истории подписывается именем Витька и отправляется только один раз.

Полная проверка выполняется только при запуске Витька либо вручную по команде
`Витёк, проверь`. Между такими проверками события передаются через долговечную
очередь `data/runtime/vitek_events.jsonl`, без пятиминутного полного опроса.
Источники сигналов:

- потеря/восстановление heartbeat, изменения стратегий и свежие ошибки NinjaTrader Bridge;
- завершение, ошибка или отмена задания NinjaTrader;
- новые задачи приложения, важные новости и ценовые сигналы;
- технические сбои и отдельно предупреждения качества AI-экспериментов;
- готовность по реальному числу approved-профилей против активных portfolio slots;
- временные окна готовых стратегий и пустые промежутки биржевой сессии;
- проваленные профили, которые не были корректно скрыты в архиве;
- целостность финансового журнала и записи `needs_review`;
- просроченные задачи.

Важная или аварийная задача внутри получает самую сильную доступную модель;
владельцу название модели и технический маршрут не показываются. Финансы
направляются Марине, стратегии и бэктесты — Толику, новости — Никите, графики —
Ивану, остальные задачи — Оркестратору. Выполняются только действия из
защищённого белого списка. Если фактического результата нет, Витёк не отмечает
задачу выполненной, а запрашивает решение владельца.

Исполнение разделено на независимые агентские дорожки: один агент не получает
две пересекающиеся задачи одновременно, но разные агенты могут работать
параллельно (до шести дорожек: Витёк, Управляющий, Марина, Толик, Никита и
Иван). В разделе Витька интерфейс каждые три секунды показывает, кто работает,
кто свободен и краткую деловую тему работы — без модели, внутренних ID и кодов.

Внутренние инциденты сохраняются отдельно от пользовательского диалога. Витёк
не показывает owner внутренние ID, event names, severity, модели и статусы
маршрутизации. Он сообщает деловой факт, одну доказательную рекомендацию и один
конкретный вопрос. Ответ «да» или «нет» в том же диалоге запускает или отменяет
всю связанную цепочку. Для реабилитации проваленной стратегии предложение
допустимо только при сохранённой проверяемой оценке выше 50%; иначе Витёк
рекомендует архив.

Новые инциденты сохраняются отдельно от признака доставки: если ручная
проверка создала инцидент без Telegram-отправки, фоновый цикл всё равно
доставит его позднее. При отсутствии плана Витёк один раз за локальный день и
неделю спрашивает цели, не объявляя отсутствие плана системной ошибкой.

## Фоновая работа

Запустите `00_INSTALL_VITEK_BACKGROUND.cmd` один раз. Установщик создаёт
пользовательскую задачу Windows `StratForge Vitek`, запускаемую при входе в
систему. Watchdog не открывает браузер и поддерживает backend на
`127.0.0.1:8765`. Если обычный backend уже работает, watchdog ждёт; когда он
закрывается, watchdog запускает фоновую замену.

Закрытие интерфейса не останавливает Telegram, heartbeat NinjaTrader и
событийный worker Витька. Внутренний браузер Codex для этой системы не
используется. Лог находится в
`logs/vitek-background.log`. Удаление: `tools/uninstall-vitek-background.ps1`.

## Команды Telegram

- `Витёк, статус`
- `Витёк, проверь`
- `да` / `нет` после вопроса Витька
- пояснение обычным текстом после вопроса Витька
- `Витёк, отдыхай 2 часа`
- `Витёк, вернись к работе`
- `Витёк, план на сегодня: цель 1; цель 2`
- `Витёк, план на неделю: цель 1; цель 2`

Критические события отправляются и во время отдыха. Опасные торговые,
финансовые и необратимые операции не входят в полномочия Витька без отдельного
подтверждения существующего защищённого workflow.

## API

- `GET /api/vitek/status`
- `GET /api/vitek/time-windows`
- `POST /api/vitek/scan`
- `POST /api/vitek/rest`, `POST /api/vitek/resume`
- `POST /api/vitek/tasks`, `POST /api/vitek/tasks/{id}`
- `POST /api/vitek/events`
- `POST /api/vitek/plans`
- `POST /api/vitek/incidents/{id}/decision`

Состояние хранится локально в `data/operations/vitek.json`. Повторные события
объединяются по стабильному fingerprint. Пустые временные окна показываются и
анализируются, но автоматическая цепочка создания новой стратегии для них не
запускается: такую задачу владелец даёт отдельно.
