# beta.84 — обязательная проверка отгрузки и честный публичный registry

## Что вошло

- `pre_release_check` стал обязательным gate точного будущего production bundle.
- Два публичных документа, которые открывались пустыми, теперь отгружаются.
- Четыре legacy-документа больше не рекламируются пользователю.

## Решения и почему

### Одна логика отбора, а не две копии

Состав отгрузки живёт в `tools/release_bundle.py`; сборщик его импортирует и
своей копии не держит — это закреплено тестом. При слиянии с `main` состав
сверен с закоммиченными константами `main`, а не принят на веру из-за чистого
merge: деревья, файлы и исключения совпали.

### Проверка выполняется внутри bundle

Четыре gate: static scan внутри собранного bundle, runtime-чтения, компиляция
Python и синтаксис отгружаемого JavaScript. Последний добавлен потому, что
незакрытая строка в ассете один раз доехала до CI и была поймана только
Windows-раннером — локально JavaScript никто не смотрел.

Каждый исторический сбой воспроизведён и gate отказал: убранный `docs/legal`,
ссылка из changelog на `docs/current`, сломанный ассет. После восстановления —
PASS.

### Публичный документ обязан ехать в artifact

Проверка runtime-чтений перестала быть списком из двух известных путей и
спрашивает registry: каждый публичный документ должен быть в отгрузке.

Это сразу нашло дефект. `ai-lab-cloud-agents` и `ai-lab-competitive-feedback`
имеют `audience: user`, то есть Documents API их показывает, но `docs/agents` не
отгружался — из artifact оба читались нулевой длины. Тот же класс, что
`docs/legal`, просто там, куда никто не смотрел. Оба добавлены поимённо:
`docs/agents/AGENTS.md` исключён намеренно, и включение дерева протащило бы его.

### Вне release root — не оправдание

Четыре `legacy-*` документа рекламировались пользователю через
`PUBLIC_DOCUMENT_IDS`, но лежат вне продукта, в материалах владельца о ведении
проекта: правила разработки, реестр приложения, заметка о развёртывании
Research Hub и годовой план. Категория `legacy`, `audience` не задан, только
чтение.

Продуктовой документацией они не были никогда, а никакой отбор файлов их
включить не может. Поэтому они убраны из публичного allowlist: Documents API их
больше не показывает пользователю, владелец по-прежнему открывает их по
привилегированному пути.

Формулировка «accepted exclusion по признаку пути» убрана из проверки целиком.
Публичный документ, которого не может достичь ни один релиз, — это
противоречие, которое надо устранить, а не исключение, которое надо записать.
