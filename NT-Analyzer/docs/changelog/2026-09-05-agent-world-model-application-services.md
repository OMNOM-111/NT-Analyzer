# Agent World: личные модели и реальные application receipts

Change summary: личная Persona может получить отдельные Provider Account и Model, выполнить явную ограниченную задачу через существующий LLM-клиент и durable worker, получить независимую проверку ответа и привязанный настоящий результат NinjaTrader/Рабочего стола в существующем SF Chat.

Status: IN DEVELOPMENT — интеграционный DEV slice. Реализация не является Canary/Production release и не заменяет owner live acceptance. Исходная точка: `486db834`; итоговый source SHA, PR и общий verification result фиксирует основной исполнитель при Git closeout. Этот scoped change не меняет номер версии и не даёт release/deploy permission.

## Что изменено

- Добавлены `model_contracts`, `model_service`, `model_evaluation`, `model_execution`, `model_transport`: собственные подключения с DPAPI-backed secret storage; test/task/disconnect; сравнение 2–3 моделей на одинаковом sealed input; реальные response/latency/token/cost receipts (неизвестная стоимость остаётся `null`). Ключи отсутствуют в SQLite, событиях, DTO, URL и журнале задач.
- Переиспользован `universal_llm.invoke_agent`, существующие reservation/account hard caps, usage ledger и `ai_budgets`. ContextVar `registry_scope` ограничивает приватный вызов одним точным адаптером без global fallback/cache. Original owner binding вызывает только сервером разрешённый существующий registry ID и сохраняет его budget caps; ordinary user не получает доступ к global registry IDs/ключам.
- Приватный транспорт: HTTPS/public DNS, pinned validated IP + TLS hostname, no redirects/proxies, exact path/port allowlist, ограниченный request/response, sanitized errors. Обычный legacy transport не изменён. Agent World invocation policy запрещает скрытый повтор DeepSeek в пределах одной reservation как для private, так и для owner-bound вызовов.
- Проверки `connection_exact`, `json_arithmetic`, `extract_facts` выполняются независимо от самооценки модели. Повтор одинакового input не увеличивает sample size; до трёх разных inputs рейтинг NEW. Court vote schema и application conformance не объявляются общим качеством модели или прибыльностью стратегии. Судьи получают изолированный sealed packet через доверенный domain callback; суд не исполняет инструменты.
- `application_chat`/`application_evidence` связывают настоящий MSG/legacy conversation ID → Intent → Task → Model/Contribution → проверенную точную спецификацию → existing NT job/Desktop command → source hashes → Execution/Outcome/Evaluation → SF Chat. Model plan PASS оставляет задачу waiting до реального отчёта/PNG. Модель не генерирует класс стратегии, не расширяет параметры/инструменты/даты и не исполняет торговые команды.
- Backtest evidence — bounded verified summary со ссылкой на полный исходный отчёт и SHA исходных файлов, не подменённый/усечённый «отчёт». Chart evidence — байты аутентифицированного сохранённого canvas PNG с проверенным SHA, не headless/synthetic изображение. PNG больше 256 KiB явно блокирует копирование; backend не обрезает и не перекодирует evidence.
- Source cancellation использует existing jobqueue/market_data: работающий NinjaTrader остаётся cancel-requested/waiting до исходного подтверждения, saved chart receipt не перезаписывается. После неоднозначного сбоя model transmit задача blocked (`model_execution_state_unknown`), без автоматического второго платного вызова.
- Retry восстанавливает typed closeout и SF Chat append без нового исполнения. Existing events inbox подтверждает финальную публикацию только после сохранения чата. Reconcile — максимум 100 scoped кандидатов за существующий Chief poll, с ограниченным непостоянным read cursor, чтобы незавершённые ранние задачи не скрывали поздние; это не новая очередь/worker.
- Адресное чтение `live_charts.details(command_id=...)` фильтруется до лимита 100 строк: новый список команд не скрывает исходный PNG ожидающей задачи. Частичные ProviderAccount/Intent creation запоминают sealed request и отвергают changed-body retry с прежним idempotency key до замены ключа/Task.
- Добавлено восстановление доставки уже сохранённого результата модели в SF Chat для ordinary own-workspace и Local owner. Это delivery-only phase существующего `agent_world_model` worker (3 попытки), а не повтор model/application execution. Исходный provider job по-прежнему имеет `max_attempts=1`. Перед обычным append создаётся durable delivery job; crash до enqueue восстанавливается существующим worker через keyset-чтение не более 100 записей раз в 30 секунд. `kind/after_id` — необязательные read selectors существующей очереди, без новой таблицы или миграции.
- Доставка повторно проверяет active auth/session, workspace history access и Agent World flags, exact original worker scope, terminal Task/checkpoint/event, независимое evidence и исходный user MSG в том же SF Chat. Внутренний Chief `history_delivery` не принимается из request envelope и разрешает только точную сохранённую model projection. После исчерпания платного entitlement можно доставить уже оплаченный результат, если чтение собственной истории ещё разрешено; новый budget/provider call отсутствует. Revoked session, чужие scope/сообщения и подделанный envelope запрещены. Inbox ack записывается после подтверждённого append; повтор после append-before-ack не создаёт второе сообщение.

## Проверки и ограничения

Тесты используют disposable SQLite, существующие jobqueue/market_data/SF Chat в tmp roots и mock provider transport. Реальный owner runtime, credentials, NinjaTrader, платные модели и внешняя сеть в этих тестах не используются. Проверяются scope, idempotency/concurrency, denied credentials/budget, response formats, evidence tamper, cancellation, restart/publication repair и отсутствие global/private state leakage.

Focused verification после финального security hardening: **226 passed** (`test_agent_world_models`, `test_agent_world_application_chat`, `test_agent_world_live_charts`, `test_ai_agents`, `test_ai_ratings`, `test_cloud_agents`), 60.60s. Отдельный integration checkpoint: **520 passed** (`test_agent_world_contracts`, `test_agent_world_storage`, `test_agent_world_compatibility`, `test_agent_world_domain_gateway`, `test_chief_agent`), 56.65s. `py_compile` для девяти затронутых runtime-модулей и двух тестовых файлов — PASS; `git diff --check` — PASS. Это scoped/legacy regression, не общий full-regression или owner live acceptance.

Delivery-recovery checkpoint поверх `ca505d83`: **235 passed**, 105.31s (`test_agent_world_model_delivery`, `test_agent_world_domain_gateway`, `test_local_worker`, `test_agent_world_application_chat`, `test_agent_world_live_gateway`). Отдельный финальный regression: **215 passed**, 87.50s (`test_chief_agent`, `test_agent_world_models`, `test_agent_world_model_delivery`). Включены 26 новых delivery/pagination/restart/security сценариев, без пропусков; все provider responses — явно mocked fixtures, не live acceptance. `py_compile` пяти изменённых runtime-модулей и нового теста, `git diff --check` — PASS. Полный regression после этой delta выполняется отдельно основным исполнителем.

Границы доступности: private paid models остаются fail-closed без существующего одобренного user/workspace budget; новый платный лимит не выдан. Custom origin разрешает только сервер. Поддерживается bounded text/OpenAI-compatible task contract, а не произвольный автономный внешний агент с неограниченными tools. Actual Desktop capture требует открытой страницы и настоящих bars; NT требует существующего каталога и работающей инфраструктуры. В этом slice нет Trading/Court auto-execution, нового job/budget engine, миграции Production DB, merge или deploy.

Current docs и External GPT Context Pack обновляет основной исполнитель вместе с общим интеграционным diff. Общий full pytest, bundle/static/context gates, Git/CI closeout и live owner acceptance — отдельные evidence, не выводятся из scoped тестов.

Delivery recovery ограничено persisted terminal/явно blocked результатом. Pending provider/application задачи не расходуют delivery retries, не финализируются и не запускаются заново фоновым selector. После трёх неудачных delivery attempts очередь сохраняет явный `failed` receipt для разбора; бесконечных скрытых повторов нет. Рейтинг не меняется при доставке: он остаётся раздельным по model/rubric и требует трёх разных inputs; connection/Court/application receipt не выдаются за общий model quality score.
