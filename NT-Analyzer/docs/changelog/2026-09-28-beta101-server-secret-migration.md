Implementation in progress: `SecretStore` selects Windows DPAPI only for Development and environment-scoped `ServerSecrets` on Canary/Production; missing server storage fails closed. Existing server ciphertext stays in FORCE-RLS PostgreSQL `sf_aw_credentials` while the independent 32-byte master key stays in the protected platform-secret store, outside PostgreSQL. The application never returns a saved API key to the browser. A trusted-process migration takes an ephemeral Local snapshot from the existing owner Agent World/registry set, preserving model/account/persona IDs, metadata, status and current sharing. The sender passes the snapshot only via strict-host-key SSH stdin; the receiver verifies owner/workspace/environment, imports typed PostgreSQL records and re-encrypts each key under the destination environment's vault key. The typed actor is a maintenance service operating on behalf of the owner, not a forged human session; receipt and audit contain only IDs, count and metadata digest. Replays are idempotent, detect changed secrets and do not re-open sharing revoked after import. The same Local plaintext source must be separately imported/re-encrypted into Production after its own approval; Canary ciphertext is not a Production credential. Server execution refuses any legacy Local DPAPI owner binding.

Provider parity: narrowly permitted private HTTPS routes include the existing accepted Gemini and Azure Foundry text models as well as OpenAI-compatible providers. The private transport still pins a public DNS address, verifies TLS, denies redirects/non-POST calls, arbitrary query parameters, private IPs and oversized requests/responses. Paid server calls must pass the existing authoritative workspace budget/usage reservation and per-call hard cap; Development's free-only private connection rule remains intact.
