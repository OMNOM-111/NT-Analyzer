# beta.90 - Root Instrument Resolution

Release summary: Бэктест принимает корень инструмента (`6M`, `MNQ`, `MES`) и сам разворачивает его в текущий конкретный контракт по тому же правилу, которое всегда использовал селектор Trading Online; спотовые инструменты не трогаются, а понятная ошибка остаётся только для корня, по которому у устройства действительно нет истории.
Release PRs: #265
Affected subsystems: server backtest instrument resolution, Trading Online instrument selector
Release impact: Пользователю больше не нужно знать контрактный месяц. Connector transport, signing/trust, auth, Release Center и market-data не затронуты.

## Что вошло

- Правило выбора front month вынесено из обработчика `/api/ops/runtime/instruments` в `jobqueue.resolve_front_month`. Семантика не менялась — перенесена как есть вместе с комментариями. Обработчик теперь вызывает эту же функцию, второго алгоритма не появилось.
- `jobqueue.resolve_root_instrument` разворачивает корень в конкретный контракт по актуальному каталогу Connector; при его отсутствии — по локальному скану.
- `create_job` резолвит корень первым шагом, до `_align_instrument_strategy_parameters`, поэтому `ContractName` в параметрах стратегии получает уже конкретный контракт, а в NinjaTrader уходит concrete instrument.
- Корень доходит до отказа только если контракта по нему действительно нет; сообщение теперь говорит про отсутствие истории, а не просит ввести месяц, которого в каталоге нет.

## Правило (без изменений, теперь в одном месте)

1. Среди контрактов с данными за последние 30 дней, чей месяц истечения ещё текущий или будущий, — самый свежий `data_last`; при равенстве ближе стоящий месяц.
2. Иначе, если «живыми» остались только контракты с прошедшим месяцем, — ближайший будущий месяц из каталога.
3. Иначе — ближайший будущий, а при его отсутствии самый свежий по `data_last`.

Спот без контрактного месяца (`BTCUSD`, `BCHEUR`) уже является исполнимым инструментом, поэтому резолвер к нему не применяется и месяц не дописывается.

## Проверено

| вход | Local (1547 инструментов, 56 корней) |
|---|---|
| `6M` | `6M 09-26` |
| `MNQ` | `MNQ 09-26` |
| `MES` | `MES 09-26` |
| `BTCUSD` | без изменений |
| `BCHEUR` | без изменений |

Селектор и бэктест дают одинаковый контракт на одних и тех же данных — закреплено параметризованными тестами. Отдельно закреплён энергетический случай: контракт с прошедшим месяцем, у которого ещё есть бары в 30-дневном окне, уступает уже листингованному будущему месяцу.
