# Как не перепутать версии StratForge

История поправки: 2026-08-02T01:55:27Z; внёс `GPT-5.5 через Codex по запросу owner`; scope: Phase 1 — привести подписи запуска к deployment environment и release channel.

Окружение и зрелость релиза показываются раздельно:

| Подпись | Что это | Как открыть |
|---|---|---|
| `РАЗРАБОТКА` / `DEV` | Текущий локальный код и локальные данные только для доработки | `START-DEVELOPMENT.cmd` |
| `ПРЕДРЕЛИЗ` / `CANARY` | Отдельное серверное окружение проверки, изолированное от Production | Отдельной кнопки пока нет; контур готовится в Phase 7 |
| `BETA` | Публичный Production с release channel `beta` | `OPEN-SERVER.cmd` или `https://app.stratforges.com/ui/` после публикации beta |
| без дополнительной подписи | Стабильный Production; слово `STABLE` пользователю не показывается | `OPEN-SERVER.cmd` или `https://app.stratforges.com/ui/` |

Термин «оригинал» не используется: он не говорит, готова ли сборка. Возле
названия приложения всегда показываются фактически полученные от backend
версия, короткий Git SHA и dirty-state. Примеры: `DEV · v1.0.0-beta.2 · abc1234 · dirty`, `CANARY · v1.0.0-beta.2 · abc1234`, `BETA · v1.0.0-beta.2 · abc1234`, `v1.0.0 · abc1234`.

`start.ps1` и `START-DEVELOPMENT.cmd` технически запрещены для Production и
всегда показывают предупреждение о локальном Development. `OPEN-SERVER.cmd`
ничего локально не запускает: сначала проверяет `/api/runtime/env`, печатает
фактические environment, версию и канал, предупреждает, если сервер не является stable Production, и только
потом открывает canonical URL. Версия Production задаётся при публикации через
защищённые переменные окружения; сервер не стартует, если build identity неполон,
dirty или противоречит окружению.

Правило именования:

- `1.2.3` — стабильный релиз;
- `1.3.0-beta.1` — beta-релиз, который тем же artifact проходит Canary и Production;
- `1.3.0-dev.4` — незавершённая локальная разработка.
